# Security model

## 要保护什么

主要目标是避免网页端模型、恶意提示或仓库中的提示注入取得下列能力：

- 读取工作区外文件或常见凭据；
- 把 MCP 参数直接变成 shell 命令；
- 修改执行策略后自行获取更高能力；
- 悄悄把本机服务暴露到公网；
- 在文件已被用户或其他工具修改后盲目覆盖。

## 信任边界

ChatGPT 和 MCP 请求都视为不可信输入。本地 `folderbridge-mcp` 进程与用户明确选择的工作区受信任。一个进程最多接受 16 个互不重复、互不包含的规范化根目录；多工作区工具调用必须使用 `server_info` 返回的 `workspace_id`，每次路径解析只在被选中的根目录内进行。`.folderbridge.json` 只有在用户从本机 CLI 批准其精确 SHA-256 后才可用于任务执行；批准记录位于工作区之外。

文件工具使用应用层路径检查和原子替换，不是内核沙箱。路径解析与真正打开文件之间仍存在理论上的 TOCTOU 窗口；如果另一个本地恶意进程能同时重写目录结构，它通常也已经拥有与本进程相当的本机权限。

## 任务执行边界

`run_task` 比任意 shell 更窄，但不等于安全执行仓库代码：

- 任务命令和参数固定在本机批准配置中；
- 禁止内联 shell/interpreter 入口；
- 不继承秘密、loader、代理等任意环境变量；
- 从清洗后的 PATH 解析可执行文件，拒绝工作区内的可执行文件冒充系统命令；
- 固定工作目录、超时、进程树终止与有界输出；
- 但 `pytest`、`npm run test` 等仍会加载仓库代码，代码可访问网络和用户可访问的文件。

因此，不可信仓库只应使用只读/文件模式，或把整个服务放在一次性 VM/容器里。

## 传输边界

本项目不提供 HTTP 服务。对 ChatGPT 网页端，建议使用 OpenAI Secure MCP Tunnel：由官方客户端从本机发起出站 HTTPS，并在本机调用 stdio 服务。本项目不接触 tunnel runtime API key。是否允许数据进入 ChatGPT、工具审批和工作区治理仍由用户的 OpenAI/ChatGPT 设置决定。
